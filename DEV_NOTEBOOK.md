## 1. Executive Summary & Repository Overview

Hydralisk is a performance-oriented fork of Hydra. All app code is hand-edited inside the built `bundle.min.js` (there is no upstream source build), plus a few standalone global scripts and a rollup-built React module. It is deployed straight from `gh-pages` to GitHub Pages. See the handbook, §1–4.

## 3. Architecture & Technical Decisions (ADRs)

- **ADR-001 (2023-08, retroactive): Patch the built bundle.** The upstream source didn't build at fork time. Trade-off: fast iteration, but no source maps or upstream merges, and diffs are hard to review.
- **ADR-002 (2025-05, retroactive): New UI goes in `modules/` (React via global UMD, rollup IIFE)** or standalone scripts, not into the bundle.
- **ADR-003 (retroactive): `xemitter` event bus is the integration point.** It lets keys, toolbar, MIDI, and the Sketch Manager share actions.
- **ADR-004 (retroactive): Static site, no runtime deps.** Remote storage is DynamoDB accessed from the browser.
- **ADR-005 (2026-10-08): Modular Plugin Architecture.** Extract all custom application logic (randomizers, mutator AST transformations, sketch library state, hotkey prevention & shortcut dispatch, speed settings, and custom shader functions) into `modules/` plugins registered with `HydraliskPlugins`.
- **ADR-006 (2026-10-13): The Visual Player is a React app.** `src/player/` uses the global UMD React 18 (`react`/`react-dom` are Rollup externals). State lives in one observable store read through `useSyncExternalStore`. Only actions write to it, and side effects (Hydra, localStorage, URL hash, Amakit) sit in services. Components are thin renderers. Timers that depend on state (automutate clock, hash sync) are hooks.

- 2026-10-18: Master Effects AST injection: Acorn parses the Hydra sketch AST to identify the rendered output buffer from `render(oX)` calls and locate the CallExpression terminating in `.out(targetBuffer)`. - 2026-10-18: Mutation Jump memory pre-calculation: The service generates a 10-step mutation chain `[S_0..S_10]` in memory where `S_0` is `baseCode` and each `S_i` is an AST mutation of `S_{i-1}`. When dialling the CC knob (0.0 to 1.0 mapped to 0 to 10), no intermediate states are written to the editor, ensuring zero latency on the press event. Master effect comments (`/* [master-effects-start:id] */ ... /* [master-effects-end] */`) and MIDI binding functions (`midi('bX', ...)`) are extracted and preserved untouched during mutation. On press at CC~=0, `preMutationState` is restored, providing musical one-touch undo. Operates headlessly with no visual indicators or triggers, accessible strictly via MIDI bindings.
- 2026-10-19: MIDI Mapping UI React Refactor: Refactored legacy `midi-mapping.js` into React components (`modules/midiMapping/`). Root cause of UI disappearing, perceived page reloading, and scroll-to-top jumps was the barefoot `modalContainer.innerHTML = ""` teardown on every action click, which destroyed all DOM nodes, lost the scroll position of `.midi-mapping-body`, and dropped input focus. The React architecture uses fine-grained reconciliation to update only the specific row badge/button, keeping scroll position locked, isolating button click events with `e.preventDefault()` / `e.stopPropagation()`, and maintaining search filter state smoothly.
