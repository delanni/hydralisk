## 1. Executive Summary & Repository Overview

Hydralisk is a performance-oriented fork of Hydra. All app code is hand-edited inside the built `bundle.min.js` (there is no upstream source build), plus a few standalone global scripts and a rollup-built React module. It is deployed straight from `master` to GitHub Pages. See the handbook, §1–4.

## 3. Architecture & Technical Decisions (ADRs)

- **ADR-001 (2023-08, retroactive): Patch the built bundle.** The upstream source didn't build at fork time. Trade-off: fast iteration, but no source maps or upstream merges, and diffs are hard to review.
- **ADR-002 (2025-05, retroactive): New UI goes in `modules/` (React via global UMD, rollup IIFE)** or standalone scripts, not into the bundle.
- **ADR-003 (retroactive): `xemitter` event bus is the integration point.** It lets keys, toolbar, MIDI, and the Sketch Manager share actions.
- **ADR-004 (retroactive): Static site, no runtime deps.** Remote storage is DynamoDB accessed from the browser.
- **ADR-005 (2026-10-08): Modular Plugin Architecture.** Extract all custom application logic (randomizers, mutator AST transformations, sketch library state, hotkey prevention & shortcut dispatch, speed settings, and custom shader functions) into `modules/` plugins registered with `HydraliskPlugins`.
- **ADR-006 (2026-10-13): The Visual Player is a React app.** `src/player/` uses the global UMD React 18 (`react`/`react-dom` are Rollup externals). State lives in one observable store read through `useSyncExternalStore`. Only actions write to it, and side effects (Hydra, localStorage, URL hash, Amakit) sit in services. Components are thin renderers. Timers that depend on state (automutate clock, hash sync) are hooks.
- **ADR-007 (2026-10-21): Automutation Transform Swaps Intentionally Disabled by Default.** Automutation triggered via keyboard shortcuts or MIDI runs strictly with numeric literal glitches (`glitchNumber`) for live performance stability and aesthetic predictability. Transform swaps are only enabled when the `Cmd` modifier is explicitly held on click or mutation. This is by design and is NOT a bug.
- **ADR-008 (2026-10-21): Canonical Sketch Loader & Persistent Undo Memory.** All sketch navigation and loading routes delegate to `modules/sketchLoader.js`, preventing in-place metadata mutation. Undo history persists to `sessionStorage`, culls every 5th mutation, and reduces to 1 (previous scene) on forward scene navigation so performers can step back to their prior sketch without retaining old mutation jitter.
